# 场景能力配置设计

## 背景

产品管理的场景方案页当前只有登录身份、移动端门户、PC端门户三个配置入口。系统已经有 `scenario_capability` 表、后端场景能力接口和前端 API 类型，但页面没有配置入口，后端也没有把场景能力限制在当前产品已关联能力内。

## 目标

在产品的场景方案中新增“能力配置”，让运营人员从该产品已经关联的能力中选择当前场景启用的能力。产品能力是场景能力的上游真源，场景不得启用未关联到当前产品的能力。

## 业务规则

- 场景能力只能选择当前场景所属产品已经关联的能力。
- 能力保存为 `scenario_capability` 记录，默认启用状态为 `1`。
- 当能力仍被某个场景方案使用时，产品能力页不允许解绑该能力，提示用户先移除场景能力配置。
- 不新增正式或证书环境数据库变更；当前实现复用既有表结构。

## 交互设计

场景卡片新增“能力配置”按钮，与登录身份、移动端门户、PC端门户并列。点击后打开弹窗，弹窗展示产品已关联能力的多选列表，并勾选当前场景已启用能力。产品未关联任何能力时，弹窗提示先到产品能力页关联能力。

## 技术设计

后端继续使用 `server/src/services/scenario.service.ts` 承载场景能力查询、添加、移除与状态更新。新增产品范围校验：添加场景能力前必须确认 `product_capability` 中存在当前场景产品与能力的绑定关系。`server/src/services/product.service.ts` 的解绑能力逻辑新增保护：若 `scenario_capability` 中存在该产品任一场景对该能力的引用，则拒绝解绑。

前端在 `src/views/product/ScenarioManage.vue` 中新增能力配置弹窗，使用 `src/api/product.ts` 的产品能力列表作为候选来源，使用 `src/api/scenario.ts` 的场景能力接口读取和保存配置。保存采用差量同步：新增被勾选但未存在的能力，移除已存在但被取消勾选的能力。

## 验证

- 后端行为测试覆盖：场景只能启用产品已关联能力；产品解绑被场景使用的能力时被阻止。
- 前端构建验证覆盖 TypeScript 类型与生产构建。
- 本地浏览器验证覆盖场景方案页新增入口和能力配置弹窗。
